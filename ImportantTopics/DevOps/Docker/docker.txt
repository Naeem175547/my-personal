1. Docker Fundamentals
Docker is a platform used to build, package, and run applications inside containers.
Why Docker?
Without Docker:

Developer
   ↓
"Works on my machine"
   ↓

   ↓
Application may fail ❌

With Docker:

Application
+ Dependencies
+ Runtime
+ Configuration
        ↓
     Container
        ↓

A container is an isolated environment where an application runs with everything it needs.

NestJS Application
      +
Node.js
      +
Dependencies
      ↓
   Container

What Docker Solves
Environment differences

Easy application portability
Consistent development and production environments

Docker Image
→ A read-only template/blueprint used to create containers.
→ Contains application code, runtime, dependencies, libraries, and required files.
→ An image itself is not running.

Docker Container
→ A running/created instance of a Docker image.
→ Uses the image as its base and provides an isolated environment for the application.
→ A container can be started, stopped, restarted, and removed.

.dockerignore
→ Tells Docker which files/folders to exclude from the build context.
It works similar to `.gitignore`, but for Docker.
Example:
node_modules/
.git/
.env
*.log
dist/

Meaning:

node_modules/
→ Do not send node_modules to Docker.

.git/
→ Do not send Git history.

.env
→ Do not send environment/secrets file.

*.log
→ Ignore all log files.

dist/
→ Do not send the dist folder.

Why use it?
Without `.dockerignore`:

Project folder
    ↓
docker build .
    ↓
Entire build context sent to Docker

With `.dockerignore`:

Project folder
    ↓
.dockerignore filters files
    ↓
Only required files sent to Docker

Example project:

Docker/
├── Dockerfile
├── .dockerignore
├── package.json
├── package-lock.json
├── index.js
├── node_modules/
├── .git/
└── .env

.dockerignore:

node_modules/
.git/
.env

Then:

COPY . .

will copy the files from the build context except the files excluded by `.dockerignore`.

Important:

.gitignore  → controls what Git ignores
.dockerignore → controls what Docker sends as build context
RUN npm install installs node_modules inside the Docker image during docker build.

Docker Volume

A Docker volume is a place to store data outside the container's temporary filesystem.
Why do we need it?
Because when a container is deleted, data inside the container can be lost.
Example:

Container
 └── MySQL
      └── Database data

If you delete the container:
docker rm my-container

the database data inside it may be lost.

With a volume:

Docker Volume
     ↓
MySQL Container

The container can be deleted/recreated, but the data remains in the volume.

Example:
docker volume create mydata

Then:
docker run -v mydata:/var/lib/mysql mysql

Here:

mydata
  ↓
/var/lib/mysql

In one line
Volume = persistent storage for Docker containers, so data survives container deletion/recreation.

starting a Consul server inside a Docker container and making its UI/API available on your machine.

Your command:
sudo docker run -d  --name consule-server -p 8500:8500  --add-host=host.docker.internal:172.17.0.1  consul:1.15

| Part                    | Meaning                                             |
| ----------------------- | --------------------------------------------------- |
| `sudo docker run`       | Create and start a new container                    |
| `-d`                    | Run in **background** (detached mode)               |
| `--name consule-server` | Give container the name `consule-server`            |
| `-p 8500:8500`          | Map **host port 8500 → container port 8500**        |
| `--add-host=...`        | Add `host.docker.internal` pointing to `172.17.0.1` |
| `consul:1.15`           | Use the **Consul version 1.15 Docker image**        |

Why Consul?
In your NestJS microservices project, Consul can be used for service discovery.

For example:

User Service
     ↓
   Consul
     ↓
Auth Service

Instead of hardcoding:
http://192.168.1.20:3001

services can register themselves with Consul, and other services can discover them.

Why port 8500?
Consul's web UI/API normally uses port 8500.

After starting it, you can access:
http://localhost:8500
Why --add-host?

This:
--add-host=host.docker.internal:172.17.0.1

adds an entry inside the container equivalent to:
host.docker.internal → 172.17.0.1

So the Consul container can refer to your Docker/host gateway using the name:
host.docker.internal

In short: you're launching Consul as a Dockerized service, exposing it on port 
8500, so your NestJS microservices can use Consul for service discovery/registration.
