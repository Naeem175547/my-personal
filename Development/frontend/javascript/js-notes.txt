-->🔹 Why Symbol?
Even if values look same, symbols are always different
let a = Symbol("id");
let b = Symbol("id");
console.log(a === b); // false ❗
👉 Both have "id" but still not equal
🔹 How to create Symbol
let id = Symbol("userId");
👉 "userId" is just a description (not the value)
🔹 Use case (important)
1. Unique keys in objects
let id = Symbol("id");
let user = {
  name: "Naeem",
  [id]: 123
};

console.log(user[id]); // 123

👉 No conflict with other keys
🔹 Hidden from normal loops
for (let key in user) {
  console.log(key);
}
👉 Symbol keys won’t appear ❗
🔹 Access Symbol keys
console.log(Object.getOwnPropertySymbols(user));
🔹 Real-life use
Avoid duplicate keys
Internal properties in frameworks
Safe object properties
⚡ Important points
Symbol is primitive
Always unique
Used as object keys
Not visible in normal loops
🔥 One-line definition
👉 Symbol = unique and immutable identifier

-->
let arr = [10, 2, 5];
arr.sort();
console.log(arr);//[10, 2, 5]  ❌ (looks unsorted)
 Why?
 Because JS converts numbers to strings:
 "10" "2" "5"
 Then compares character by character:
 "1" comes before "2" → so "10" comes before "2"
 So it sorts like dictionary order, not numeric order.
 🧠 Lexicographic (string) sorting rule
 "10" < "2"   // true (because '1' < '2')
 That’s why it behaves “wrong” for numbers.
 ✅ Correct way: use comparator function
let arr = [10, 2, 5];
arr.sort((a, b) => a - b);
console.log(arr); // [2, 5, 10]
// Descending order
arr.sort((a, b) => b - a);
how comparator works
(a, b) => a - b
| Result | Meaning          |
| ------ | ---------------- |
| < 0    | a comes before b |
| > 0    | b comes before a |
| 0      | unchanged        |
| Case               | Behavior                   |
| ------------------ | -------------------------- |
| `sort()`           | treats elements as strings |
| `sort((a,b)=>a-b)` | numeric sort               |

-->// 🔥 Lexical Environment + Closure Reference (FINAL NOTES)

🧠 What is Lexical Environment?

A Lexical Environment is an internal JavaScript structure created whenever a function or block runs.
It represents the scope of that code.
It stores:
👉 Variables (variable bindings: name → value)
👉 Functions (function bindings: name → function object)
👉 A reference to its outer lexical environment (scope chain)


📦 Simple meaning:
Lexical Environment = Scope + Variables + Outer scope reference


🧠 Function Binding
Function binding means storing a function’s name mapped to its actual function object inside the Lexical Environment.


🧠 Function Object (Important)

A JavaScript function is internally an object.
It contains:
👉 executable code
👉 properties (name, length, etc.)
👉 hidden reference to outer scope ([[Environment]] for closure)


🔥 Key Concept (Closure base)

A Lexical Environment is stored in heap memory,
and it is kept alive if a function is still referencing it.

👉 This is what enables CLOSURE.


🧠 Closure Rule

A child function has its own Lexical Environment,
and it also contains a reference to its outer Lexical Environment.

👉 Variables are NOT copied.
👉 They are accessed through the scope chain.


📦 Final Simple Definition:

Lexical Environment = A structure that defines scope, stores variables & functions, and links to outer scope.
Closure = When a function remembers its outer Lexical Environment even after the outer function has finished execution.
