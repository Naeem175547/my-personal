--> MONGODB  INTRODUCTION

MongoDB is a NoSQL document-oriented database used to store 
large amounts of data in a flexible and scalable way.
 It stores data in the form of documents
 instead of tables and rows used in relational databases like MySQL.
MongoDB stores data in BSON (Binary JSON) format, which is similar to
 JSON.

Example of a Document:

{
   "name": "Naeem",
   "age": 21,
   "skills": ["Java", "MongoDB"]
}
========================
JSON VS BSON
========================

JSON (JavaScript Object Notation) is a text-based
data format used for storing and exchanging data.

BSON (Binary JSON) is a binary-encoded format used
internally by MongoDB to store documents.

--------------------------------------------------
EXAMPLE OF JSON
--------------------------------------------------

{
   "name": "Naeem",
   "age": 21,
   "skills": ["Java", "MongoDB"]
}

--------------------------------------------------
EXAMPLE OF BSON
--------------------------------------------------

BSON is stored in binary format, so it is not
human-readable like JSON.

MongoDB converts JSON-like documents into BSON
before storing them.

--------------------------------------------------
MAIN DIFFERENCES
--------------------------------------------------

Feature            JSON                 BSON
---------------------------------------------------------
Format             Text-based           Binary format
Readability        Human-readable       Not human-readable
Speed              Slower parsing       Faster parsing
Data Types         Limited              More data types
Size               Smaller              Slightly larger
Used In            APIs/Web             MongoDB internally

--------------------------------------------------
DATA TYPES
--------------------------------------------------

JSON Supports:
* String
* Number
* Boolean
* Array
* Object
* Null

BSON Supports:
* String
* Integer
* Boolean
* Array
* Object
* Date
* Binary Data
* ObjectId
* Decimal128
* Timestamp
* Regexp
* Null
and more...

--------------------------------------------------
WHY MONGODB USES BSON
--------------------------------------------------

MongoDB uses BSON because:

* Faster data traversal
* Better performance
* Supports more data types
* Efficient storage and retrieval

--------------------------------------------------
IMPORTANT POINT
--------------------------------------------------

When you write data in MongoDB shell or Node.js,
it looks like JSON, but MongoDB actually stores
it internally as BSON.

--------------------------------------------------
CONCLUSION
--------------------------------------------------

JSON is a lightweight text format mainly used for
data exchange, while BSON is a binary format used
by MongoDB for faster storage and processing.

--------------------------------------------------
MONGODB STRUCTURE
--------------------------------------------------

Database
   └── Collection
           └── Document

Example:

College (Database)
   └── Students (Collection)
           └── {name:"Naeem", age:21}

--------------------------------------------------
MAIN FEATURES OF MONGODB
--------------------------------------------------

1. Document-Oriented Database
   - Data is stored as documents.

2. NoSQL Database
   - Does not use tables and rows.

3. Flexible Schema
   - Different documents can have different fields.

4. High Performance
   - Fast read and write operations.

5. Scalability
   - Supports horizontal scaling using sharding.
   sharding->
   Sharding is a method of distributing data across
   multiple servers to handle very large databases
   and high traffic efficiently.
In MongoDB, sharding is used for horizontal scaling.

Instead of storing all data on one server,
MongoDB divides data into smaller parts called
shards and stores them on different servers.


6. Replication
   - Provides backup and high availability using replica sets.

--------------------------------------------------
SCHEMA-LESS PROPERTY
--------------------------------------------------

Documents inside the same collection can have
different structures.

Example:

{ "name": "Ali" }

{ "name": "Sara", "age": 20 }

--------------------------------------------------
MONGODB TERMINOLOGY
--------------------------------------------------

MongoDB Term          SQL Equivalent
-----------------------------------------
Database              Database
Collection            Table
Document              Row
Field                 Column

--------------------------------------------------
ADVANTAGES OF MONGODB
--------------------------------------------------

* Flexible data model
* Easy scalability
* Faster development
* Good for real-time applications
* Works well with JavaScript and MERN stack

--------------------------------------------------
DISADVANTAGES OF MONGODB
--------------------------------------------------

* More memory usage
* Complex joins are difficult
* Less strict consistency than SQL databases

--------------------------------------------------
APPLICATIONS OF MONGODB
--------------------------------------------------

* Web applications
* MERN stack projects
* Chat applications
* E-commerce websites
* Content management systems
* Big data applications

note->ISO STANDARD DATE FORMAT

ISO standard date format is an international
standard used to represent date and time.

MongoDB uses ISO 8601 format for dates.

==================================================

BASIC FORMAT

YYYY-MM-DDTHH:MM:SSZ

==================================================

MEANING OF EACH PART

YYYY  → Year
MM    → Month
DD    → Day

T     → Separates date and time

HH    → Hours
MM    → Minutes
SS    → Seconds

Z     → UTC timezone

==================================================

EXAMPLE

2026-05-27T12:45:30Z

Explanation:

2026  → Year
05    → May
27    → Day

12    → Hour
45    → Minute
30    → Second

Z     → UTC timezone

UTC TIMEZONE (Simple Meaning)
UTC = World's common reference time
UTC is the main standard time of the world.
All countries compare their local time with UTC.

Example:
If UTC time is:
12:00 PM
Then India time becomes:
05:30 PM
Because India is 5 hours 30 minutes ahead of UTC.

In ISO Date:
2026-05-27T12:45:30Z

Z means:
UTC time
==================================================

IN MONGODB

Example:

{
   createdAt:ISODate("2026-05-27T12:45:30Z")
}

==================================================

WHY ISO FORMAT IS USED

* International standard
* Avoids date confusion
* Easy sorting
* Timezone support
* Used in databases and APIs

==================================================

COMMON CONFUSION

Wrong / Confusing Formats:

05/06/2026
06/05/2026

Different countries may read them differently.

ISO Format avoids confusion:

2026-05-06

-->  BSON SCHEMA VALIDATION IN MONGODB
MongoDB Schema Validation
MongoDB allows us to validate documents before inserting them into a collection.

Validation checks:
• Required fields
• Data types
• Value ranges
• Allowed values
• String patterns etc.
It helps keep data correct and consistent.

Syntax
db.createCollection("collection_name",{
   validator:{
      $jsonSchema:{
         
      }
   }
})


$jsonSchema
$jsonSchema is used to define validation rules using JSON Schema format.

Example:

validator:{
   $jsonSchema:{
      
   }
}

Important Fields in $jsonSchema
1. title
Used to give schema name.
title:"Student"

2. required
Defines mandatory fields.
required:["name","age"]
If these fields are missing, insertion fails.

3. properties
Used to define rules for each field.

properties:{
   name:{
      
   },
   age:{
      
   }
}

Field Validation Keywords
1. bsonType
Defines datatype of field.
Example:

bsonType:"string"


Common bsonType Values

"string"   → Text
"int"      → Integer
"double"   → Decimal number
"bool"     → true/false
"array"    → Array
"object"   → Object
"date"     → Date
"objectId" → MongoDB ObjectId


2. description
Adds message/documentation for validation rule.
description:"Name must be string"

3. minimum
Defines minimum numeric value.
minimum:18

4. maximum
Defines maximum numeric value.
maximum:60


5. enum
Allows only specific values.
enum:["BCA","BTech","BSc"]
Only these values are accepted.
Full Example

db.createCollection("student",{
   validator:{
      $jsonSchema:{
         title:"Student",
         required:["name","age","course"],
         properties:{
            name:{
               bsonType:"string",
               description:"Name must be string and required"
            },
            age:{
               bsonType:"int",
               minimum:18,
               maximum:60,
               description:"Age must be between 18 and 60"
            },
            course:{
               bsonType:"string",
               enum:["BCA","BTech","BSc"],
               description:"Course must be BCA, BTech or BSc"
            }
         }
      }
   }
})

Valid Document

db.student.insertOne({
   name:"Rahul",
   age:20,
   course:"BTech"
})
Inserted successfully.

Invalid Document
db.student.insertOne({
   name:"Rahul",
   age:70,
   course:"MBA"
})

Fails because:
• age > 60
• MBA not in enum list

➡️ Array validation:(skills is array)
db.createCollection("student",{
   validator:{
      $jsonSchema:{
         properties:{
            skills:{
               bsonType:"array",
               items:{
                  bsonType:"string"  //this define value of array elements
               },
               description:"Skills must contain only strings"
            }
         }
      }
   }
})

➡️ Object validation(address is object)

db.createCollection("student",{
   validator:{
      $jsonSchema:{
         properties:{
            address:{
               bsonType:"object",
               properties:{
                  city:{
                     bsonType:"string"
                  },
                  pincode:{
                     bsonType:"int"
                  }
               },

               description:"Address must be valid object"
            }
         }
      }
   }
})

➡️ ADDING VALIDATION TO ALREADY EXISTING COLLECTION
MongoDB uses collMod command to add or modify
validation rules in an existing collection.
Syntax

db.runCommand({
   collMod:"collection_name",

   validator:{
      $jsonSchema:{
         
      }
   }
})
Explanation

* collMod works only on existing collections.
* Validation applies on future inserts/updates.
* Old documents remain unchanged.

Important Notes
• Validation works only on insert/update.
• Existing documents are not checked automatically.
• MongoDB is schema-less, but validation adds rules.
• Validation improves data consistency.

UPDATE COMMANDS IN MONGODB

MongoDB provides updateOne(), updateMany()
and replaceOne() methods to modify documents.

1. updateOne()
Used for:
✅ Update first matching document

Syntax:
db.collection.updateOne(
   {filter}, // selects document(s) to update
   {$set:{field:value}} // defines the changes to apply
)

Example:
db.student.updateOne(
   {name:"Rahul"},
   {$set:{age:25}}
)

Output:

{
   acknowledged:true,
   matchedCount:1,
   modifiedCount:1
}

2. updateMany()
Used for:
✅ Update all matching documents

Syntax:

db.collection.updateMany(
   {filter},
   {$set:{field:value}}
)

Example:
db.student.updateMany(
   {course:"BTech"},
   {$set:{status:"Active"}}
)
Output:
{
   acknowledged:true,
   matchedCount:5,
   modifiedCount:5
}

3. replaceOne()
Used for:
✅ Replace entire document

Example:

db.student.replaceOne(
   {name:"Rahul"},
   {
      name:"Rahul",
      age:22,
      course:"BCA"
   }
)

Output:

{
   acknowledged:true,
   matchedCount:1,
   modifiedCount:1
}

==================================================

COMMON UPDATE OPERATORS

🔷 $set
Updates or adds field.
Example:
{$set:{age:25}}


🔷 $unset
Removes field.
Example:
{$unset:{age:""}}



🔷 $inc
Increases numeric value.
Example:
{$inc:{age:2}}
//age will be increased by 2


🔷 $mul
Multiplies numeric value.
Example:
{$mul:{salary:2}}
//salary will be multiplied by 2


🔷 $rename
Renames field.
Example:
{$rename:{"name":"fullName"}}


🔷 $min
Updates only if new value is smaller.
Example:
{$min:{age:18}}


🔷 $max
Updates only if new value is greater.
Example:
{$max:{age:60}}


🔷 $currentDate
Sets current date.
Example:
{$currentDate:{updatedAt:true}}

UPDATE OPERATORS FOR ARRAYS IN MONGODB



🔷 $push
Used for:
✅ Add element to array
Example:
{$push:{skills:"React"}}

Before:
{
   skills:["Java","MongoDB"]
}

After:
{
   skills:["Java","MongoDB","React"]
}


🔷 $addToSet
Used for:
✅ Add element only if not already present

Example:
{$addToSet:{skills:"React"}}

Before:
{
   skills:["Java","React"]
}

After:
{
   skills:["Java","React"]
}
(No duplicate added)


🔷 $pop
Used for:
✅ Remove first or last element

Example:
{$pop:{skills:1}}
Removes last element
Example:
{$pop:{skills:-1}}
Removes first element



🔷 $pull
Used for:
✅ Remove matching element from array

Example:
{$pull:{skills:"Java"}}

Before:
{
   skills:["Java","MongoDB","React"]
}

After:
{
   skills:["MongoDB","React"]
}


🔷 $pullAll
Used for:
✅ Remove multiple specified elements from an array

Syntax:
{$pullAll:{field:[value1,value2,...]}}
Example

{$pullAll:{skills:["Java","React"]}}

Before:
{
   skills:["Java","MongoDB","React","NodeJS"]
}
After:
{
   skills:["MongoDB","NodeJS"]
}



🔷 $each

Used for:
✅ Add multiple values with $push

Example:

{
   $push:{
      skills:{
         $each:["React","NodeJS"]
      }
   }
}


🔷 $set
Used for:
✅ Update array element by index

Example:

{$set:{"skills.0":"Python"}}

Before:
{
   skills:["Java","MongoDB"]
}
After:
{
   skills:["Python","MongoDB"]
}


Example Command

db.student.updateOne(
   {name:"Naeem"},
   {$push:{skills:"React"}}
)

* updateOne() updates first matching document.
* updateMany() updates all matching documents.

--> FIND COMMANDS IN MONGODB

MongoDB provides various methods to retrieve
documents from a collection.

1. find()
Used for:
✅ Fetch all matching documents
Syntax:
db.collection.find()

Example:
db.student.find()

Output

[
   {name:"Rahul", age:20},
   {name:"Aman", age:21}
]

2. findOne()

Used for:
✅ Fetch first matching document

Syntax:
db.collection.findOne({filter})
Example:
db.student.findOne({name:"Rahul"})

Output
{
   name:"Rahul",
   age:20
}

4. findBy ObjectId
Example:

db.student.find({
   _id:ObjectId("665f1ab23cd45ef678901234")
})


5. find().pretty()

Used for:
✅ Display formatted output
Example:
db.student.find().pretty()

6. Limit Documents
Example:
db.student.find().limit(2)

7. Skip Documents

Example:
db.student.find().skip(2)


In MongoDB, these two give the same result:
db.student.find().skip(2).limit(2)
db.student.find().limit(2).skip(2)

MongoDB applies skip before limit internally,
regardless of the order written in the query.


==================================================

8. Sort Documents

Ascending:
db.student.find().sort({age:1})

Descending:
db.student.find().sort({age:-1})

==================================================

9. Count Documents

db.student.countDocuments()

db.student.find().count()

==================================================

10. Projection
Projection is used to select which fields should
be returned in the result.
Syntax:
db.collection.find(
   {filter},
   {projection}
)
or
db.collection.find(
   {filter}
).projection({})


.Include Fields
Example:

db.student.find(
   {},
   {name:1, age:1}
)
Output:

{
   _id:ObjectId("..."),
   name:"Rahul",
   age:20
}



.Exclude _id Field
Example:

db.student.find(
   {},
   {name:1, age:1, _id:0}
)

Output:

{
   name:"Rahul",
   age:20
}



.Exclude Fields

Example:
db.student.find(
   {},
   {age:0}
)

Output:

{
   _id:ObjectId("..."),
   name:"Rahul",
   course:"BTech"
}


.Rules
1 → Include field
0 → Exclude field


IMPORTANT POINT

You cannot mix inclusion (1) and exclusion (0)
in the same projection except for _id.

Valid:
{name:1, age:1, _id:0}
Invalid:
{name:1, age:0}

Output

{
   name:"Rahul",
   age:20
}

MongoDB Aggregation Framework
The MongoDB Aggregation Framework is used to process, filter, transform, and analyze data in collections.
It works like a pipeline where documents pass through multiple stages.
Collection → Stage1 → Stage2 → Stage3 → Output
 aggregation works like a pipeline, and the output of the last stage is returned as the final result.
--------------------------------------------------
Basic Syntax

db.collection.aggregate([
   { stage1 },
   { stage2 },
   { stage3 }
])
--------------------------------------------------

1. $match
Used to filter(find) documents.
Example:
db.users.aggregate([
   {
      $match: { age: { $gte: 18 } }
   }
])

SQL Equivalent:
WHERE age >= 18

Yes, if you do not use $match, aggregation will process all documents in the collection.

--------------------------------------------------
2. $project
Used to select fields or create new fields.
Example:
db.users.aggregate([
   {
      $project: {
         name: 1,
         email: 1,
         _id: 0
      }
   }
])

 $project with Custom Field
Used to create new fields.

Example:
db.users.aggregate([
   {
      $project: {
         fullName: {
            $concat: ["$firstName", " ", "$lastName"]
            //$gt: ["$age", 20] → Checks if age is greater than 20.so this will so true false
         },
         age: 1
      }
   }
])

--------------------------------------------------

3. $sort
Sort documents.
Example:
db.users.aggregate([
   {
      $sort: { age: -1 }
      //$sort: { age: -1, name: 1 } → First sort by age descending, then if age is same sort by name ascending.
   }
])

1  → ascending
-1 → descending


$sortByCount → Groups documents and sorts them by count in descending order.

Example:
db.users.aggregate([
   {
      $sortByCount: "$city" → Groups documents by city and sorts them by number of documents in descending order.
   }
])

Output:
[
   { _id: "Delhi", count: 5 },
   { _id: "Mumbai", count: 3 },
   { _id: "Pune", count: 2 }
]

--------------------------------------------------

4. $limit
Limit number of documents.
Example:
db.users.aggregate([
   {
      $limit: 5
   }
])
--------------------------------------------------
5. $skip
Used for pagination.
Example:
db.users.aggregate([
   { $skip: 10 },
   { $limit: 10 }
])

Example->
db.users.aggregate([

# 6. `$group`

The `$group` stage is used in the MongoDB Aggregation Framework to:

- Group documents based on a field
- Perform calculations on grouped data
- Generate summarized results

It works similarly to `GROUP BY` in SQL.

---

# Basic Syntax

db.collection.aggregate([
   {
      $group: {
         _id: "$fieldName"
      }
   }
])
# Important Point

The `_id` field inside `$group` decides on which field the grouping will happen.
Documents having the same value of that field become one group.

# Example Collection

[
   { name: "Ali", course: "BTech", marks: 80 },
   { name: "Rahul", course: "BTech", marks: 70 },
   { name: "Aman", course: "BCA", marks: 90 },
   { name: "Sara", course: "BCA", marks: 60 }
]

db.student.aggregate([

         _id: "$course"
      }
   }
])

## Output

   { _id: "BTech" },
   { _id: "BCA" }
]
# Example 2 — Count Students Per Course

db.student.aggregate([
   {

         _id: "$course",

      }
   }
])


## Output

[
   { _id: "BTech", count: 2 },
   { _id: "BCA", count: 2 }

count: { $sum: 1 }

Commonly used in statistics and analytics

12. $bucket
Groups documents into ranges.

Example:
Syntax
db.collection.aggregate([
{

    boundaries: [0, 18, 30, 50],
    default: "Other",
    output: {

    }
  }
}
])
Meaning:
groupBy

Field on which grouping happens.
groupBy: "$age"

→ Group documents based on age.
boundaries
Defines ranges.

boundaries: [0, 18, 30, 50]

Creates buckets:
0 → 18
18 → 30
30 → 50

Rule:
lower <= value < upper

Example:
18 goes in second bucket
30 goes in third bucket


default
Stores values outside boundaries.

default: "Other"

If age is:
less than 0
greater/equal 50

then document goes into "Other" bucket.

Output Example
[
  {
    _id: 0,
    count: 2
  },
  {
    _id: 18,
    count: 5
  },
  {
    _id: 30,
    count: 3
  },
  {
    _id: "Other",
    count: 1
  }
]

_id
Represents bucket starting boundary.

-->$bucketAuto
 automatically creates buckets with almost equal number of documents.
You do not give boundaries manually.

$out
$out is used to save aggregation result into a collection.

It permanently writes data to database.

Syntax
db.collection.aggregate([
  { pipeline stages },
  {
    $out: "newCollection"
  }
])
Example
db.students.aggregate([
{
  $match: { marks: { $gt: 50 } }
},
{
  $out: "passedStudents"
}
])
Meaning
Aggregation result stored in passedStudents
Collection created automatically if not exists
Existing collection data gets replaced
Result
students  → original collection
passedStudents → new saved collection
Important

✅ Changes database permanently
✅ Last stage in pipeline

| `$out`       | Normal Aggregation |
| ------------ | ------------------ |
| Saves result | Temporary output   |
| Changes DB   | Does not change DB |

$merge
$merge is used to save aggregation results into a collection
 without fully replacing it.

It can:
Insert new documents
Update existing documents
Merge data

Syntax
db.collection.aggregate([
  { pipeline stages },
  {
    $merge: "targetCollection"
  }
])

Example
db.students.aggregate([
{
  $match: { marks: { $gt: 50 } }
},
{
  $merge: "passedStudents"
}
])

Meaning

Result documents are merged into passedStudents.

If document exists:
update it

If document does not exist:
insert it

$merge supports:

into
on
whenMatched
whenNotMatched

Syntax
{
  $merge: {
    into: "targetCollection",
    on: "_id",
    whenMatched: "merge",
    whenNotMatched: "insert"
  }
}
Meaning

into
Target collection name.

into: "students"
Save result into students.

on
Field used to match documents.

on: "_id"
MongoDB compares _id values.

whenMatched
What to do if matching document already exists.

Options
"replace"
"merge"
"keepExisting"
"fail"
Example
whenMatched: "merge"

Merge fields with existing document.

whenNotMatched
What to do if no matching document exists.

Options
"insert"
"discard"
"fail"
Example
whenNotMatched: "insert"

Insert new document.

Full Example
db.newData.aggregate([
{
  $merge: {
    into: "students",
    on: "_id",
    whenMatched: "merge",
    whenNotMatched: "insert"
  }
}
])

$unionWith is used to combine documents from multiple collections.

Like SQL UNION.

Syntax
db.collection1.aggregate([
{
  $unionWith: "collection2"
}

students

 { name: "Ali" }

teachers

  $unionWith: "teachers"
}
])

 { name: "Ali" },

db.students.aggregate([

Meaning
Combine collections
Optional filtering using pipeline
Does not remove duplicates automatically

$fill is used to fill missing or null field values in documents.

Mostly used in:

Time-series data
Missing records
Analytics
Syntax
{
  $fill: {
    output: {
      fieldName: {
        value: value
      }
    }
  }
}
Example
Before
[
 { name: "Ali", marks: 90 },
 { name: "Sara", marks: null },
 { name: "John" }
]
Query
db.students.aggregate([
{
  $fill: {
    output: {
      marks: {
            value: 0
          }
    }
  }
}
])
Output
[
 { name: "Ali", marks: 90 },
 { name: "Sara", marks: 0 },
 { name: "John", marks: 0 }
]
Meaning
null or missing → replaced with 0

Other Fill Methods
1. value
Fixed value filling.

marks: {
  value: 0
}

2. linear
Fills values using interpolation.

marks: {
  method: "linear"
}

3. locf
Last Observation Carried Forward.
Uses previous value.

marks: {
  method: "locf"
}
