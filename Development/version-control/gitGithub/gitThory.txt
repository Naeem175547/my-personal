========================================================
1. WHAT IS GIT?
========================================================

Git is a Version Control System.
that tracks the changes in code .

It helps:
- Track code changes
- Save project history
- Work with teams
- Restore old code versions

Example:
Like game save points for your code.

========================================================
2. WHAT IS GITHUB?
========================================================

GitHub is a cloud platform to store Git repositories online.
it allows developers to store and manage code using git.

Git = Tool
GitHub = Website/platform using Git

Uses:
- Backup code online
- Team collaboration
- Pull Requests
- Open source projects

# =====================================================
# GIT INSTALLATION & CONFIGURATION COMMANDS
# =====================================================

# Check Git installation
git --version


# Configure Git username
git config --global user.name "Your Name"


# Configure Git email
git config --global user.email "youremail@gmail.com"


# Set default editor (VS Code example)
git config --global core.editor "code --wait"

# Other editor examples:
# git config --global core.editor "notepad"
# git config --global core.editor "vim"


# Enable colored output
git config --global color.ui auto


# Check all Git configurations
git config --list


# Check only username
git config --global user.name


# Check only email
git config --global user.email


# Open global config file manually
git config --global --edit


# Location of global config file
# Windows:
C:/Users/YourName/.gitconfig

# Linux/Mac:
~/.gitconfig

========================================================
11. BRANCHES
========================================================

Branch = Separate working line.

Check branches:
git branch

Create branch:
git branch feature

Switch branch:
git checkout feature

Create + switch:
git checkout -b feature

New command:
git switch feature

Create + switch:

git switch -c feature

Delete branch:

git branch -d feature

Force delete:

git branch -D feature

Rename branch:

git branch -m oldname newname

git branch -r  → Shows only remote branches (branches available on GitHub like origin/main).
git branch -a  → Shows all branches (both local branches + remote branches together).


========================================================
12. MERGE
========================================================

Combine branches.

Example:

git checkout main
git merge feature

This merges feature into main.

notes->
1. Create new branch from main

git checkout main
git checkout -b feature-branch

------------------------------------------------

2. New branch gets all code from main at creation time

main  ---------> feature-branch

------------------------------------------------

3. After branch creation

- Changes in main will NOT come automatically to feature-branch
- Changes in feature-branch will NOT come automatically to main

------------------------------------------------

4. Bring latest changes from main to feature-branch

git checkout feature-branch
git merge main

------------------------------------------------

5. Simple Flow

git checkout main
git checkout -b feature-branch

# do work in feature-branch

git checkout main
# new changes added in main

git checkout feature-branch
git merge main

------------------------------------------------
Result:
feature-branch now contains latest changes from main

========================================================
14. REMOTE (FULL CONCEPT)
========================================================

Remote = Online repository connection.

Check remotes:
git remote (list remote name)
git remote -v

Add remote:
git remote add name url

Example:
git remote add origin https://github.com/user/project.git

Git allows multiple remotes in a single repository.

Remove remote:
git remote remove origin

rename remote:
git remote rename origin

Change remote URL:
git remote set-url origin new_url

# =====================================================
# 22. GIT RESET
# =====================================================

# Used to:
# ✔ Unstage files
# ✔ Undo commits
# ✔ Move HEAD to previous commit


# -----------------------------------------------------
# 1. REMOVE FILE FROM STAGING
# -----------------------------------------------------

git reset file.txt

# Removes file from staging area
# Changes stay in working directory


# -----------------------------------------------------
# 2. SOFT RESET
# -----------------------------------------------------

git reset --soft HEAD~1

# Removes last commit
# Keeps changes staged


# -----------------------------------------------------
# 3. MIXED RESET (DEFAULT)
# -----------------------------------------------------

git reset HEAD~1

# Removes last commit
# Keeps changes in working directory
# Unstages changes


# -----------------------------------------------------
# 4. HARD RESET
# -----------------------------------------------------

git reset --hard HEAD~1

# Removes last commit
# Deletes all changes permanently


# -----------------------------------------------------
# 5. RESET TO SPECIFIC COMMIT
# -----------------------------------------------------

git reset --hard commit_id(commit hash)

# Example:
git reset --hard a1b2c3d


# -----------------------------------------------------
# 6. RESET STAGING AREA ONLY
# -----------------------------------------------------

git reset

# Unstages all files
# Keeps file changes


# -----------------------------------------------------
# HEAD~1 MEANING
# -----------------------------------------------------

# HEAD     = current commit
# HEAD~1   = one commit before
# HEAD~2   = two commits before


# -----------------------------------------------------
# WARNING
# -----------------------------------------------------

# HARD RESET deletes changes permanently
# Use carefully

git clone  → Copies an entire remote repository to your local system and automatically adds the remote connection.
git remote → Manages remote repository connections (add, remove, view, or change remotes) in an existing Git project.
If you push directly to main branch:
git push origin main

Then changes go directly into main.
No Pull Request (PR) is needed.

------------------------------------------------

If you push to another branch:

git push origin feature

Then you usually create a Pull Request (PR)
to merge feature branch into main branch.

------------------------------------------------

Common Team Workflow:

1. Create feature branch
2. Do changes
3. Push feature branch
4. Create Pull Request
5. Review + Merge into main

------------------------------------------------

PR is mainly used when:
- Working in teams
- Reviewing code
- Protecting main branch
